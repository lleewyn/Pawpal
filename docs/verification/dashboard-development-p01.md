**RPCs, permissions and refresh**

- Operations uses direct paginated table reads, not an operations aggregate RPC: 500 rows per request, 5,000-row ceiling per paged read, ordered by ID. Ten displayed tasks per page is client pagination over that bounded result. Evidence: `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:13`, `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:117`.
- Base SELECT policies require `<table>.read`, including embedded relations: appointment/item, sales order/detail, return, staff/schedule, inventory/product/variant/reservation, support and review. Today's pet-name expansion also needs `pet_profile.read`. Fixed-role permission checks require an active, unbanned staff identity with one valid role and no pending password change. STAFF uses its separate work view; the management dashboard is not its data access path. RLS denial can yield empty rows rather than a permission exception, so an empty result is not proof of a permitted, complete read. Evidence: `scripts/database/v1/002_rules.sql:232`, `scripts/database/v1/165_admin_fixed_roles.sql:114`, `pages/admin/admin.js:1054`.
- Related RPCs are separate contracts: M044 `get_admin_dashboard_cashflow` requires payment/refund permissions plus a financial role, aggregates succeeded receipts/refunds on their success/completion dates, and allows 31 dates per call; M088 `get_admin_dashboard_low_stock` is an invoker read requiring inventory/product/variant permissions and returns at most four physical-stock rows. M241 business metrics and M246/M247 plan RPCs do not provide an operations task feed. M247 retains a target-only plan, superseding M246 behavior. No finance change is proposed. Evidence: `scripts/database/v1/044_admin_dashboard_cashflow.sql:2`, `scripts/database/v1/088_admin_dashboard_low_stock.sql:2`, `scripts/database/v1/241_admin_remaining_read_budget.sql:2`, `scripts/database/v1/247_dashboard_target_only.sql:25`.
- Realtime invalidates/refetches with an 800 ms debounce; fallback polling is 60 seconds while visible. M183 disables published DELETE events and adds owner-scoped workspace signals; the dashboard listens for workspace invalidation. Subscription success alone does not verify table publication or signal delivery. Evidence: `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:301`, `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:976`, `scripts/database/v1/183_safe_realtime_signals.sql:20`, `pages/admin/admin-access.js:13`.

**Navigation and concrete risks**

- **Cached selection:** dashboard navigation writes selected-ID/subtab storage keys and clicks the sidebar. Destinations also retain in-memory selected IDs, which can take precedence: appointment `selectedBookingId`, order `selectedOrderId`, complaint `currentTicketId`. Require a cold-open and an A-to-B cached-open check; synchronize the target state or use the existing detail opener after module activation. Complaint paging can include an off-page record via `p_context` UUID or ticket code. Evidence: `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:356`, `pages/admin/modules/services/services.js:1901`, `pages/admin/modules/services/services.js:1940`, `pages/admin/modules/orders/orders.js:886`, `pages/admin/modules/complaints/complaints.js:1345`, `scripts/database/v1/248_complaint_sla_order.sql:114`.
- **Return constraint:** a return UUID is not a support-ticket UUID. Current working-copy navigation resolves `sales_order_id` and opens the parent order, whose detail renders return requests; it does not select an exact return or prove a linked complaint. Missing-parent fallback opens the order-complaint list only. Label this action “Mở đơn gốc”; do not promise an exact complaint/return detail. Evidence: `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:361`, `pages/admin/modules/orders/subtabs/tab-order-detail.js:379`, `scripts/database/v1/001_schema.sql:1424`.
- **Hotel/taxi constraint:** sources exist (`hotel_booking.check_in_at/check_out_at/status/room_id`; `taxi_trip.outbound_at/return_at/status/driver_staff_id`, both linked by `appointment_id`), and service detail loads both. Operations does not query these resources. Today's start-date agenda omits ongoing stays started earlier, today's checkout and taxi return legs on another day; generic concurrency is not room capacity or driver availability. Open the parent appointment; defer dedicated hotel/taxi dispatch and capacity claims. Evidence: `scripts/database/v1/001_schema.sql:750`, `scripts/database/v1/001_schema.sql:778`, `pages/admin/modules/services/services.js:1354`, `pages/admin/modules/dashboard/subtabs/operations-metrics.js:448`, `pages/admin/modules/dashboard/subtabs/operations-metrics.js:701`.
- **Threshold mismatch:** keep existing dashboard rules: pending 15 minutes / over 30 minutes, start-soon 1 hour, unassigned 24 hours, late arrival 30 minutes, preparation 4 hours, returns 48 hours, first response 4 hours, support resolution 24 hours for high/urgent and 48 otherwise. However M248 already defines stored `sla_due_at`: urgent 4, high 24, medium 48, low 72 hours. Dashboard does not read it or customer-response deadlines. These are dashboard alert thresholds, not verified contractual SLA breaches. Also `updated_at` changes on general edits, so order preparation age is not time since confirmation. Evidence: `pages/admin/modules/dashboard/subtabs/operations-metrics.js:18`, `pages/admin/modules/dashboard/subtabs/operations-metrics.js:631`, `scripts/database/v1/248_complaint_sla_order.sql:2`, `scripts/database/v1/217_complaint_followup.sql:3`, `scripts/database/v1/002_rules.sql:4`.
- **Completeness/time risk:** the 5,000-row ceiling can omit urgent work; offset pagination is not a transactional snapshot. Failed/truncated sources must stay visibly incomplete, never imply zero work. Live mode stops polling, so crossing a threshold without a database event need not rerender; the resolved “today” date also needs a midnight rollover check. Quality's resolved count describes tickets created in the period that are now closed, not resolutions performed during the period. Evidence: `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:117`, `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:628`, `pages/admin/modules/dashboard/subtabs/tab-dashboard-operations.js:886`, `pages/admin/modules/dashboard/subtabs/operations-metrics.js:559`.
